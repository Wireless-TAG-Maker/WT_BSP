# WT9932S31-TINY 工厂示例

同时启用摄像头、SDMMC、RGB、SW2 按键和 J1 的 UVC + CDC 复合设备。
摄像头型号和引脚由 BSP 管理，应用只包含 `wt_bsp.h`。
**SD 录像默认关闭**，默认只采集并检查摄像头、检查 SD 卡，不创建录像目录或文件。

## 构建与接线

使用 ESP-IDF v6.1 及以上版本，默认摄像头为 GC2145。

```sh
WT_BSP_BOARD=WT9932S31-TINY idf.py --preview set-board
idf.py --preview menuconfig
idf.py --preview build
idf.py --preview -p /dev/ttyACM0 flash monitor
```

在 `WT BSP -> Camera sensor` 选择实际接入的 GC2145 或 OV3660。
两款传感器共用 SCCB 地址，采用编译时选择，换型号后重新构建、烧录。
更换摄像头或 SD 卡前断开两根 USB 线，彻底断电。
型号配置不匹配也会导致探测失败；SD 正常时基准灯色为蓝色。正常识别日志中的芯片 ID 应为
GC2145 `0x2145` 或 OV3660 `0x3660`。

需要测试录像时，在 `S31 factory -> Enable SD card recording` 中启用
`CONFIG_WT_FACTORY_ENABLE_SD_RECORDING`，重新构建、烧录后生效。
关闭该项时不编译 AVI 写入器，分段时长选项也隐藏；原有工程升级后的首次构建
同样默认关闭。连续录像会占用卡容量并消耗写入寿命，建议仅在需要时启用。

- J2：USB Serial/JTAG，用于供电、烧录和日志，不选择 USB 摄像头模式。
- J1：USB OTG，连接电脑并枚举后选择 UVC + CDC，不要求打开 CDC 串口。
- SD 卡：已格式化且有剩余空间的测试卡；挂载失败不会自动格式化。
- SW2/BOOT：每按一次切换 RGB 的熄灭/点亮状态；启用录像且处于离线模式时，同时暂停/恢复录制。
  USB 模式和录像关闭时也可切换亮灭。SW1/EN 是复位键。

## RGB 指示灯

启动检测完成后，RGB 使用下表提示当前状态。以下规则适用于本 S31 工厂示例，
离线模式和 J1 USB 模式使用相同的故障颜色。

| RGB 颜色 | 含义 |
| --- | --- |
| 绿色 | SD 卡与摄像头检测正常，按键回调和 CDC 控制台正常。 |
| 红色 | SD 卡未接入、初始化/挂载失败，或运行中卡状态/读写检查失败；摄像头正常。 |
| 蓝色 | 摄像头未接入、型号不匹配、初始化/探测失败或采集异常；SD 卡正常。 |
| 黄色 | SD 卡与摄像头同时异常。 |
| 白色 | SD 卡与摄像头正常，但按键回调注册或 CDC 控制台启动失败。 |
| 熄灭 | 通过 SW2/BOOT 手动关闭灯光；不能据此判断外设是否正常。 |

SD 卡或摄像头故障时，优先显示对应故障色；只有两者均正常时，才使用白色提示
按键回调或 CDC 控制台故障。SD 故障不阻止正常摄像头继续提供 UVC；可用的 CDC
诊断接口也继续保留。

启动时 RGB 默认允许点亮，检测期间先短暂显示红色；此时的红色不作为 SD 卡
检测结论。检测完成后显示对应状态色，各点亮通道亮度保持为 24。

**SW2/BOOT 每按一次切换 RGB 的亮/灭状态。** 第一次按下熄灭，再按一次重新
点亮。熄灭期间仍更新硬件诊断，重新点亮时显示最新状态色。USB 模式和录像关闭时
也保持该行为；复位恢复点亮。故障颜色仍按当前诊断状态选择。

上述提示在 BSP 初始化成功、RGB 可用后生效；BSP 整体初始化失败时，仍按原有流程
回滚资源并退出，错误通过 J2 日志报告。

## 运行模式与录像

硬件正常时，各模式的采集、录像和按键行为如下：

| 状态 | 摄像头与 SD | SW2/BOOT |
| --- | --- | --- |
| 默认配置，启动时未连接 J1 | 采集后丢弃图像，检查 SD，不写录像 | 切换 RGB 亮灭 |
| 已启用录像，启动时未连接 J1 | 持续录制到 SD | 切换 RGB 亮灭并暂停录制 |
| 已启用录像，离线暂停 | 继续采集检查摄像头，停止写录像 | 切换 RGB 亮灭并恢复录制 |
| J1 完成 USB 枚举 | UVC 输出；不写录像，CDC 可查询状态和读取已结束的录像 | 切换 RGB 亮灭，保留原离线暂停状态 |

录像暂停不再单独显示蓝色；SD 和摄像头正常时，暂停与运行的基准色均为绿色。
录像关闭时仍要求 SD 卡可挂载且状态正常，缺卡的基准色仍为红色。灯色不表示
是否正在录像，也不能作为可以取卡的依据。修复 SD 故障后重新启动；不支持带电换卡。

**从 USB 模式恢复离线模式：先拔掉 J1，保留 J2 供电，再按 SW1/EN 复位。**
当前板卡没有 J1 VBUS 检测线，J2 供电时仅拔掉 J1 不会可靠清除 USB 枚举状态，
绿灯也不表示已恢复录像。示例不以电脑休眠或停止 USB 通信代替拔线判断。
复位后会重新检查硬件；仅在启用录像时以新文件编号开始录像。
暂停状态和熄灯状态均不跨复位保留。

## 录像文件

以下写入行为仅在启用 `CONFIG_WT_FACTORY_ENABLE_SD_RECORDING` 时发生：

- 文件位于 `/sdcard/recordings/rec_000001.avi`，为 MJPEG AVI，直接保存 JPEG 帧。
- 按已有文件的最大编号继续递增，已有 `.avi` 和 `.avi.part` 均保留，不循环覆盖。
- 默认每 60 秒或 64 MiB 结束一个分段；时长可在 `S31 factory` 中调整。
- 按键暂停或切换 USB 时，先写索引、更新帧率和长度、同步并关闭文件，再提供读取。
- 正在写入的文件带 `.avi.part` 后缀，成功结束才改为 `.avi`。
- 突然断电可能使当前分段不完整，且文件系统仍有写缓存风险；取卡前先暂停录制，
  确认 `Recording paused` 日志；若有正在录制的分段，还需确认 `Saved ...`
  日志表示收尾成功，再断电取卡。灯色不能代替日志确认。示例不修复断电留下的 `.part` 文件。
- 空间不足或 I/O 失败保留已有文件并报告 SD 故障，不自动删除历史录像。

GC2145 为 1600×1200、标称 8 FPS；OV3660 为 640×480、标称 25 FPS。
AVI 根据采集时间计算实际平均帧率，SD 写入速度会影响帧率。
工厂复合设备的两款摄像头均使用 UVC Bulk。实测 OV3660 原等时配置在 CDC/SD
大文件读取并发时出现不完整 JPEG 帧，切换 Bulk 后通过并发回归；独立 UVC 示例
保留 OV3660 原有的等时配置。

## CDC 命令

J1 在电脑上枚举为 `Wireless-Tag Camera` 摄像头和 CDC ACM 串口。
串口波特率可用 115200，需置 DTR；命令使用 ASCII 并以换行结束。
J2 日志独立输出，避免污染 CDC 二进制录像数据。

| 命令 | 返回 |
| --- | --- |
| `ping` | `pong\n` |
| `status` | 一行 JSON：模式、`recording_enabled` 录像配置、暂停状态、摄像头/SD 状态、录制帧数、完成分段数、文件名、空闲堆 |
| `list` | 多行 `FILE 文件名 字节数`，最后 `END\n` |
| `get rec_000001.avi` | `DATA 字节数\n`，随后精确数量的文件字节，最后 `\nEND\n` |

`list/get` 仅允许 USB 模式且存储正常时使用；只读取该目录下符合录像命名的
已完成 AVI，不接受任意路径。传输中断后重新打开串口并重新发起请求。
单个客户端顺序发送命令；读取完整响应后再发下一条。
录像关闭时仍可读取已有 AVI；卡上没有录像目录时，`list` 返回空列表 `END\n`。
此时离线模式为 `monitor`，`recording_enabled=false`，录像计数保持为 0。

## 本地验证

AVI 容器测试需要主机 C 编译器和 Python Pillow，不需要连接开发板：

```sh
python tests/test_avi.py
```

测试实际调用录像写入器，再独立解析 RIFF 和索引、解码每个 JPEG，覆盖奇偶
长度帧、采集时间、文件编号安全边界对应的禁止覆盖、满索引和非法帧拒绝。
地址及未定义行为检查由编译器 sanitizer 启用。若当前 shell 的 ESP 交叉工具链
覆盖了主机 `as`，请在主机编译工具优先的 PATH 下运行。

默认配置应验证离线采集检查正常、SW2 每按一次在绿色与熄灭之间切换、录像计数保持为 0、
不创建录像目录或文件，以及 UVC/CDC 和已有录像读取正常。
开启录像后的实机验收应覆盖离线启动、SW2 暂停/恢复、分段录像读取和解码、接入 J1 后录像
计数停止、UVC 与 CDC 并行工作、拔掉 J1 后复位恢复录像，以及断电移除
SD/摄像头后的独立故障灯色。两种录像配置及 USB 模式都应验证逐次切换亮灭、熄灭期间
故障状态变化后重新点亮显示最新状态色、复位恢复点亮；同时检查日志能区分录像运行与暂停。
当前 GC2145 固件已烧录，用户于 2026-10-20 确认本次修改无问题；本轮验证范围
见下文，旧固件的历史记录不作为新行为的独立通过证据。
两种摄像头分别构建和验证。独立 OV3660 示例的等时 USB 传输优先在原生 USB
主机测试；此前本机 WSL USB/IP 链路会截断等时帧。该限制不应直接套用于本工厂
示例的 Bulk 配置。
